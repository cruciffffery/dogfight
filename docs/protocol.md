# Протокол dogfight v1

Транспорт — WebSocket (`/ws`). Текстові кадри — JSON (лобі, чат, службові); бінарні — гарячий шлях (команди і знімки), якщо клієнт обрав `codec: "binary"` у `join` (за замовчуванням).

**Порядок байтів: little-endian у всіх багатобайтових полях.** Кодек пише через `DataView` з явним прапорцем `littleEndian = true`; `Float32Array`/`Uint16Array` для мережі не використовуються, бо пишуть у порядку байтів машини.

Версія: байт 5 кожного бінарного кадру = `1`. Невідома версія → `CodecError` на клієнті, `close(4001)` на сервері.

## Текстові повідомлення

| Напрям | `type`              | Поля                                                                                       |
| ------ | ------------------- | ------------------------------------------------------------------------------------------ |
| C→S    | `join`              | `room` (`[a-z0-9-]{1,32}`), `name` (1–16 літер/цифр/` _.-`), `codec?` (`json` \| `binary`) |
| C→S    | `chat`              | `text` (1–200 символів після trim)                                                         |
| C→S    | `ping`              | `t` (число, клієнтський час)                                                               |
| C→S    | `input`             | `seq` (u32 ≥ 1), `cmds` (1–3 команди) — лише з `codec: "json"`                             |
| C→S    | `leave`             | —                                                                                          |
| S→C    | `welcome`           | `playerId`, `shipId`, `room`, `arena`, `tickRate`, `codec`                                 |
| S→C    | `roster`            | `players: [{ id, name, shipId, skin }]`                                                    |
| S→C    | `chat`              | `from`, `name`, `text`, `t`                                                                |
| S→C    | `pong`              | `t` (відлуння)                                                                             |
| S→C    | `snapshot`          | як бінарний, у JSON — лише з `codec: "json"`                                               |
| S→C    | `shutdown`, `error` | — / `code`, `message`                                                                      |

Кожне текстове повідомлення має `v: 1`. Сервер відхиляє невідомі поля.

## Команда (1 байт у бінарному input)

```
bit 0–1  turn + 1      (0 = ліво, 1 = прямо, 2 = право; 3 — помилка)
bit 2    thrust
bit 3    brake
bit 4    fire
bit 5–7  0 (інакше — помилка)
```

## 0x01 — input (клієнт → сервер)

| Зсув | Тип    | Поле                                                          |
| ---- | ------ | ------------------------------------------------------------- |
| 0    | u8     | `0x01`                                                        |
| 1    | u32    | `seq` — номер НАЙНОВІШОЇ команди                              |
| 5    | u8     | версія `1`                                                    |
| 6    | u8     | `n` — кількість команд (1–3)                                  |
| 7    | u8 × n | команди від найстарішої (`seq − n + 1`) до найновішої (`seq`) |

Розмір: `7 + n` байт (10 при n = 3). Кожна команда надсилається тричі поспіль — сервер відкидає вже бачені `seq`, тож втрата одного-двох пакетів поспіль нічого не губить.

## 0x10 — snapshot (сервер → клієнт)

### Заголовок (14 байт)

| Зсув | Тип | Поле                                               |
| ---- | --- | -------------------------------------------------- |
| 0    | u8  | `0x10`                                             |
| 1    | u32 | `tick`                                             |
| 5    | u8  | версія `1`                                         |
| 6    | u32 | `ack` — останній оброблений `seq` ЦЬОГО отримувача |
| 10   | u16 | кількість сутностей                                |
| 12   | u8  | кількість подій                                    |
| 13   | u8  | кількість рахунків                                 |

### Сутність (13 байт + доповнення за типом)

| Зсув | Тип | Поле                                           |
| ---- | --- | ---------------------------------------------- |
| 0    | u16 | `id` (молодші 16 біт id сутності)              |
| 2    | u8  | `kind`: 1 ship, 2 bullet, 3 asteroid, 4 pickup |
| 3    | f32 | `x`                                            |
| 7    | f32 | `y`                                            |
| 11   | i16 | `angle` у тисячних радіана (`round(a · 1000)`) |

| `kind`   | Доповнення                                                                                               | Байт |
| -------- | -------------------------------------------------------------------------------------------------------- | ---- |
| ship     | `vx` f32, `vy` f32, `hp` u8, `flags` u8 (1 thrust, 2 destroyed, 4 shield, 8 rapid, 16 homing), `skin` u8 | 11   |
| bullet   | `owner` u16 (id корабля), `seq` u16 (молодші 16 біт seq вводу, що її створив), `homing` u8               | 5    |
| asteroid | `radius` u8, `variant` u8, `homing` u8                                                                   | 3    |
| pickup   | `ptype` u8 (0 shield, 1 rapid, 2 homing)                                                                 | 1    |

Вибухи (`Explosion`) не передаються: клієнт малює їх сам за подією `exploded`.

### Подія (13 байт)

| Зсув | Тип | Поле                                                        |
| ---- | --- | ----------------------------------------------------------- |
| 0    | u8  | `type`: 1 fired, 2 hit, 3 exploded, 4 picked, 5 scored      |
| 1    | f32 | `x`                                                         |
| 5    | f32 | `y`                                                         |
| 9    | u16 | `a` — id сутності (власник / ціль / підібрав)               |
| 11   | u16 | `b` — fired: 0; exploded: kind; picked: ptype; scored: очки |

### Рахунок (6 байт)

`shipId` u16, `score` u32.

### Розмір

`14 + Σ(13 + extra[kind]) + 13·events + 6·scores`; кадр, у якому після останнього поля лишились байти, — помилка.

## Точність квантування

- Позиції `Float32`: на арені ≤ 1920 px крок float32 ≤ 1.2·10⁻⁴ px — у тисячі разів менше за піксель.
- Кут `Int16` у 1/1000 рад: крок 0.057°. На відстані 1000 px (більше за пів арени) це 1 px зміщення напрямку — менше за радіус кулі (3 px). Діапазон ±32.767 рад покриває [−π, π).
- Швидкість корабля — `Float32`, бо від неї залежить звірка передбачення: квантований кут/швидкість дали б корекції навіть без помилок.
